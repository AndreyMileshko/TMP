# 1. Назначение

Reference Data — Colors — функциональная область Capability Reference Data платформы TMP. Она ведёт:

- каталог **одиночных цветов TMP** (только код, без наименования);
- **глобальные соответствия** текстовых обозначений цвета «СуперОкна 7» (СО7 / 1DEL) парам «цвет внутри + цвет снаружи» TMP;
- **общесистемный переключатель** «Автоматически сопоставлять цвета СО7».

Область предоставляет механизм **разрешения цвета на границе импорта STXT**. Она не владеет заказами, спецификациями, складскими или производственными данными и не изменяет их.

Пользовательский результат: при включённом переключателе известные обозначения СО7 автоматически разрешаются в коды TMP; неизвестные непустые обозначения разрешаются пользователем в **едином окне**, в котором также доступны для просмотра и разового переопределения все уже сопоставленные строки. Пользователь всегда может оставить исходный текст или ввести допустимый свой цвет без добавления его в каталог.

---

# 2. Цели

1. Единый каталог одиночных цветовых исполнений TMP без карточек и наименований.
2. Много текстовых обозначений СО7 → одна пара TMP.
3. Любое сочетание цвета внутри и снаружи без каталога комбинаций.
4. Сопоставление по **текстовому** значению поля «Цвет» строки спецификации `.stxt`, без `CLRNO`.
5. При выключенном переключателе импорт полностью сохраняет прежнее поведение.
6. При включённом переключателе — разрешение всех цветов файла за один проход в одном окне.
7. Единый путь заказа и материалов для справочных и разовых цветов.
8. Отсутствие ретроспективных изменений утверждённых спецификаций и документов.
9. Воспроизводимое начальное заполнение из согласованного Excel.

**Architecture rules:**

- Каталог цветов **не** является Material Master; Warehouse его не читает и не использует как материальную идентичность.
- Order Management, Warehouse и Production **не** имеют compile-time зависимости от Reference Data; Reference Data не зависит от них. Границы закрепляются ArchUnit-тестами.
- Reference Data не изменяет данные других Capability; межсхемные FK и JOIN отсутствуют.
- Существующая модель ACTIVE и immutable Specification сохраняется. Импортированный заказ после ACTIVE ничем не отличается от заказа, созданного другим способом.
- Изменения каталога, соответствий и переключателя влияют только на будущие импорты.
- Будущие справочники могут добавляться в Capability Reference Data отдельными решениями; универсальный framework справочников не создаётся.

# 4. Термины и синтаксис

**Одиночный цвет TMP** — запись каталога с уникальным кодом. Наименования нет.

**Модификация цвета** — часть кода после вертикальной черты `|`.

**Двухстороннее исполнение** — пара одиночных цветов в порядке **внутри / снаружи**.

**Обозначение СО7 (исходный текст)** — значение третьего поля («Цвет») строки спецификации `.stxt` после штатного разбора парсером (`trim`). Не равно `CLRNO`.

**Ключ СО7** — нормализованная форма исходного текста (§6.2), по которой ищется соответствие.

**Глобальное соответствие** — запись «ключ СО7 → цвет внутри + цвет снаружи», применяемая к будущим импортам при включённом переключателе.

**Разовое разрешение** — выбор итогового цвета только для конкретной строки спецификации текущего импорта; глобальные соответствия не изменяет.

**Свой цвет** — введённый пользователем текст, не являющийся кодом каталога; допустим при соблюдении ограничений Order Management (§10).

**Итоговый цвет** — строка, записываемая в `color` строки спецификации.

## 4.1 Разделители

```text
|  = модификация одного цвета TMP           (RAL7016|30, KDB74-Z8|МАСС)
/  = разделение итогового цвета на внутри/снаружи, внутри первым   (Белый/RAL7016|30)
```

Примеры одиночных цветов: `Белый`, `00`, `RAL7016`, `RAL7016|30`, `RAL7016|МУАР`, `KDB74-Z8`, `KDB74-Z8|МАСС`, `KDB74-Z8|ПРИТВОР`.

Примеры итоговых цветов пары: `Белый/RAL7016`, `Белый/RAL7016|30`, `KDB74-Z8|МАСС/Белый`.

- Обратный слеш `\` не используется ни в кодах, ни как разделитель.
- `/` в **исходном тексте СО7** (например `RAL7016/30т`) — часть текста; исходный текст **никогда** не разбирается по `/`.
- Структурный разделитель полей STXT — точная подстрока `" / "`; это уже реализовано парсером (`StxtBlockParser.DELIMITER`), парсер не меняется.

## 4.2 Код `00` и «Без цвета»

- Код TMP `00` означает **неокрашенный профиль**.
- Текст СО7 `Без цвета` **не** эквивалентен `00` автоматически; соответствия `Без цвета → 00` в начальных данных нет и по умолчанию не создаётся.
- `Без цвета`, `Цвет` и любые другие текстовые обозначения обрабатываются **одним и тем же** механизмом (§8); особой логики для «обобщённых» названий нет.

# 5. Каталог одиночных цветов TMP

## 5.1 Логическая модель

| Поле | Смысл | Правила |
|---|---|---|
| `id` | Технический ID | UUID; пользователю не показывается |
| `code` | Код одиночного цвета | Обязательный; хранится в исходном написании; **неизменяемый** после сохранения |
| `code_key` | Ключ уникальности | `code.toUpperCase(Locale.ROOT)`, вычисляется в Java; UNIQUE |
| `active` | Активен / архив | По умолчанию `true` |
| технические поля | `version`, `created_at`, `updated_at`, `created_by`, `updated_by` | Database Specification §5 |

Полей `name`, `group`, `finish`, `inside`, `outside` нет.

## 5.2 Правила кода

1. После `trim` не пустой; хранится без краевых пробелов.
2. Длина ≤ **31** символа — гарантирует, что итоговая пара `inside/outside` (≤ 63) укладывается в ограничение Order Management `color ≤ 64`. Максимальная длина кода в начальных данных — 16.
3. Не содержит `/` и `\`.
4. Содержит не более одного `|`; части до и после `|` не пустые.
5. Уникальность **регистронезависимая** по `code_key` (`ral7016` отклоняется при наличии `RAL7016`); сохранённое написание не изменяется.
6. Код — единственный видимый пользователю идентификатор.

## 5.3 Жизненный цикл

| Операция | Правило | Право |
|---|---|---|
| Создать | Новый уникальный код (§5.2); создаётся активным | `reference.color.edit` |
| Изменить код | **Запрещено** — сохранённый код неизменяем | — |
| Удалить | **Запрещено** — физическое удаление сохранённых цветов отсутствует в API и UI | — |
| Архивировать | С подтверждением влияния; атомарно отключает связанные соответствия | `reference.color.edit` |
| Восстановить | Возвращает цвет в активные; соответствия **не** активируются автоматически | `reference.color.edit` |

Архивирование:

1. UI запрашивает число связанных **активных** соответствий (цвет используется внутри **или** снаружи) и показывает предупреждение с этим числом.
2. После подтверждения в **одной транзакции Reference Data**: цвет получает `active = false`, все активные соответствия, ссылающиеся на него, получают `active = false`. Строки соответствий физически не удаляются.
3. Optimistic locking по `version` цвета; при конфликте — понятная ошибка и перечитывание.
4. Восстановление не включает ранее отключённые соответствия; их включает уполномоченный пользователь отдельно (§6.4).
5. Существующие документы, спецификации, остатки и производственные данные не изменяются. Проверок использования кода в заказах / на складе нет (межмодульные проверки не вводятся).

## 5.4 Начальное заполнение

Источник — лист «Цвета TMP» согласованного Excel: **860** уникальных кодов (639 RAL всех исполнений + 219 кашировок всех исполнений + `Белый` + `00`), все активны, уникальны с учётом и без учёта регистра; суффиксы `|30` 213, `|МУАР` 213, `|МАСС` 73, `|ПРИТВОР` 73; `/`, `\`, пробелов в кодах нет. Каждая модификация — отдельная запись. Комбинации внутри/снаружи заранее не создаются.

# 6. Глобальные соответствия СО7

## 6.1 Логическая модель

| Поле | Смысл | Правила |
|---|---|---|
| `id` | Технический ID | UUID |
| `source_text` | Исходный текст СО7 | Обязательный; хранится после `trim`; ≤ 64; неизменяемый после создания |
| `source_key` | Ключ СО7 (§6.2) | Вычисляется в Java; UNIQUE независимо от активности |
| `inside_color_id` | Цвет внутри | FK → `reference.colors(id)` |
| `outside_color_id` | Цвет снаружи | FK → `reference.colors(id)` |
| `active` | Активность | По умолчанию `true` |
| технические поля | `version`, `created_at`, `updated_at`, `created_by`, `updated_by` | Database Specification §5 |

Коды внутри/снаружи и итоговый цвет — **вычисляемые** при чтении; дублирующие поля не хранятся. Столбец Excel «Основание» и условные числовые ID Excel в рабочую модель не переносятся.

**Кардинальность:** любое число ключей СО7 → одна пара TMP; один ключ СО7 → **ровно одна** запись соответствия (активная или отключённая). Второе правило для того же ключа создать нельзя — изменяется существующее.

## 6.2 Нормализация ключа СО7

```text
source_key = upper_ROOT( collapse_ws( trim_ws( text ) ) )
```

- `trim_ws` — удаление краевых пробельных символов (`Character.isWhitespace` и U+00A0);
- `collapse_ws` — замена каждой последовательности таких символов **одним** пробелом U+0020;
- `upper_ROOT` — `String.toUpperCase(Locale.ROOT)` (локаленезависимо).

Запрещено: удалять пробелы целиком (`RAL 7016` ≠ `RAL7016`), заменять `Ё`, удалять/изменять `/`, `|`, суффиксы (`мат`, `т`, `притв`) и любые различия цветов. Ключ вычисляется **только в Java** (Reference Data); SQL-функции `upper()` / `lower()` PostgreSQL для ключей не используются; seed содержит заранее вычисленные литералы, совпадающие с Java-нормализацией (проверяется тестом).

Проверено на 245 ключах: коллизий нет.

## 6.3 Итоговый цвет пары

```text
если inside.code == outside.code:  display = inside.code
иначе:                             display = inside.code + "/" + outside.code
```

Порядок всегда **внутри / снаружи**. Строку формирует только Reference Data. Каталог двухсторонних сочетаний не создаётся.

## 6.4 Операции

| Операция | Правило | Право |
|---|---|---|
| Просмотр, поиск, фильтр по активности | — | `reference.color.view` |
| Создать | Ключ не существует; обе стороны — **активные** цвета каталога | `reference.color-mapping.edit` |
| Изменить пару | Обе стороны активные; влияет только на будущие импорты | `reference.color-mapping.edit` |
| Включить | Обе стороны активные | `reference.color-mapping.edit` |
| Отключить | Всегда допустимо | `reference.color-mapping.edit` |
| Удалить | Физическое удаление записи соответствия; освобождает ключ | `reference.color-mapping.edit` |
| Сохранить из окна импорта | §11 | `reference.color-mapping.edit` |

Все изменения — optimistic locking по `version`. Изменение / отключение / удаление соответствия не затрагивает ранее созданные спецификации.

## 6.5 Начальное заполнение

Источник — лист «Сопоставления СО7»: **245** активных соответствий (244 из `Сопоставление_цветов_1DEL_TMP_v3_согласовано.xlsx` + `Белый → Белый`). Все 245 ключей уникальны точно и после нормализации §6.2; все 490 ссылок разрешаются в 860 кодов; у всех 245 внутри = снаружи (это не ограничивает будущие пары); 33 исходных текста содержат `/` и остаются одиночными исполнениями (например `RAL7016/30т → RAL7016|30`).

Не загружаются: 393 двухсторонних обозначения аналитической выборки без принятой пары, 725 неподтверждённых записей, прочие исследовательские строки, соответствие `Без цвета → 00`.

# 7. Переключатель автоматического сопоставления

«**Автоматически сопоставлять цвета СО7**» — одна общесистемная настройка, принадлежащая Reference Data.

| Значение | Поведение импорта |
|---|---|
| `OFF` (начальное) | Полностью прежний сценарий: `parse → preview → confirm` без обращения к соответствиям, без окна разрешения, без кнопки «Проверить цвета», без изменения цветов |
| `ON` | Сопоставление и окно разрешения по §8–§9 |

- Настройка общая для всех пользователей, не персональная.
- Чтение — §15.2; изменение — только `reference.color-setting.edit`; optimistic locking.
- Изменение настройки не переобрабатывает старые заказы и не меняет существующие спецификации.

# 8. Единое окно разрешения цветов

## 8.1 Принцип

Все текстовые обозначения СО7 (`Цвет`, `Без цвета`, `RAL Татпроф`, `RAL 7016 мат`, `Белый/RAL7016`, `RAL7016/30т`, …) проходят **один и тот же** механизм и **одно** окно. Отдельных окон, классификаций или алгоритмов для «формальных» / «обобщённых» названий нет. Последовательные popup-окна по каждому цвету запрещены.

## 8.2 Состав строк

Окно содержит **все строки спецификации с непустым цветом** всех заказов файла:

- автоматически сопоставленные (активное глобальное соответствие найдено) — с предзаполненной парой;
- неизвестные (соответствия нет или оно отключено) — без выбранного значения.

Строки с пустым цветом (`null` после разбора) в окно не попадают, остаются `null` и разрешения не требуют.

Колонки строки: заказ; изделие (номер позиции / код / наименование); № строки спецификации в изделии; артикул; наименование материала; исходный текст СО7; состояние («Сопоставлено» / «Требует выбора» / «Изменено вручную»); **«Внутри TMP»**; **«Снаружи TMP»**; итоговый цвет; «Сохранить сопоставление в справочнике»; ошибка проверки. Фильтр «Требуют выбора / Все» и фильтр/группировка по исходному тексту.

## 8.3 Варианты разрешения строки

Для каждой строки независимо:

1. **Пара TMP** — выбор цвета внутри и цвета снаружи из **активного** каталога (поиск по коду). Итоговый цвет — §6.3.
2. **Оставить исходный текст** — итоговый цвет = исходный текст СО7 без изменений.
3. **Свой цвет** — ввод допустимого произвольного текста (§10). Каталог не пополняется.

Одинаковые исходные тексты **не** объединяются принудительно: разные строки (в одном изделии и в разных изделиях / заказах) могут получить разные итоговые цвета.

## 8.4 Переопределение автоматически сопоставленных строк

- Пользователь может изменить пару (или выбрать «оставить исходный» / «свой цвет») для любой автоматически сопоставленной строки.
- Переопределение действует **только** для этой строки текущего импорта и **не** изменяет глобальное соответствие.
- Для ключей, у которых уже есть запись соответствия (активная или отключённая), флажок «Сохранить сопоставление в справочнике» недоступен; изменение глобального правила выполняется только на экране «Справочники → Цвета».

## 8.5 Массовые действия

Осознанные команды над явно указанным множеством строк:

- «Применить пару к выделенным строкам»;
- «Применить пару ко всем строкам с тем же текстом СО7» (сравнение по ключу §6.2);
- «Оставить исходный текст» — для выделенных / для всех строк, требующих выбора;
- «Свой цвет» — для выделенных строк.

Массовое применение пары переносит **обе** стороны и затрагивает только указанные строки.

## 8.6 Флажок «Сохранить сопоставление в справочнике»

- Доступен только при праве `reference.color-mapping.edit`; без права скрыт / недоступен, а разрешение цвета для текущего заказа остаётся полностью доступным.
- Доступен только для строки, у ключа которой **нет** записи соответствия, и только при выборе **пары из двух активных цветов каталога** (не для «исходного» и «своего» цвета).
- По умолчанию включён, когда доступен.
- При выключенном флажке разрешение действует только для текущего импорта.
- Если в одном импорте строки с одинаковым ключом и отмеченным флажком получили **разные** пары, окно показывает предупреждение «Для одного текста СО7 выбраны разные пары — сопоставление не будет сохранено»; импорт не блокируется, глобальное соответствие для этого ключа не сохраняется. Одинаковые пары для одного ключа сохраняются один раз.

## 8.7 Открытие окна и «Проверить цвета»

- Переключатель `ON` и есть хотя бы одна неизвестная непустая строка (или итоговое значение автоматически сопоставленной строки не проходит проверку §10) → окно открывается автоматически как часть импорта, до построения preview.
- Переключатель `ON` и все непустые цвета сопоставлены → окно **не** открывается; preview строится по автоматически разрешённым цветам.
- В preview при `ON` и наличии строк с непустым цветом доступна команда **«Проверить цвета»**, открывающая **то же** окно с текущими выборами; после «Применить» preview перестраивается.
- «Применить» доступно, когда у каждой строки есть допустимое итоговое значение. «Отмена» при автоматическом открытии прекращает подготовку импорта: заказы и соответствия не создаются. «Отмена» после «Проверить цвета» сохраняет прежние выборы и прежний preview.

- Сохраняются: мультизаказный файл, единый порядок preview/confirm, обязательные поля, уникальность номера заказа, document-engine flow, атомарность (нет частично импортированного файла), source-neutral граница, запрет persistent `ImportMetadata` / checksum registry / Firebird-коннектора.

# 10. Проверка итогового цвета

Существующие ограничения Order Management для `SpecificationLine.color`: длина ≤ **64** (`VARCHAR(64)`) и запрет плейсхолдеров `UNKNOWN`, `N/A`, `NA`, `IMPORT`, `—`, `-`, `NONE`, `TBD` (регистронезависимо после `trim`; `CommercialPlaceholderValidator`). Сегодня `OrderImportValidator` цвет не проверяет: недопустимый цвет проходит preview и падает на confirm общей ошибкой.

Правила при включённом переключателе:

1. Каждое итоговое значение (пара, исходный текст, свой цвет) проверяется **до preview** в окне разрешения / координаторе.
2. Проверка выполняется через **read-only публичный контракт Order Management** в `com.tmp.order.api.imports` (единственный источник правил — домен OM). Контракт аддитивный; Order Management не зависит от Reference Data; `OrderImportValidator` не изменяется.
3. Свой цвет: после `trim` не пустой, ≤ 64, не плейсхолдер. Исходный текст можно оставить, если он удовлетворяет тем же правилам.
4. Ошибки показываются на уровне поля строки понятным русским текстом, например: «Цвет длиннее 64 символов», «Значение "N/A" не допускается как цвет», «Укажите цвет».
5. Допустимые произвольные тексты разрешены; дополнительных предупреждений, подтверждений или складских действий из-за разового цвета нет.
6. При `OFF` поведение импорта не меняется (в т.ч. момент ошибки confirm для недопустимого цвета).
7. Новых ограничений Warehouse / Production не вводится.

# 11. Сохранение глобальных соответствий из импорта

1. Сохранение выполняется **только после успешного** `confirm`, **отдельной транзакцией** Reference Data, вызовом `saveMappingsFromImport` с кандидатами (исходный текст, цвет внутри, цвет снаружи) из строк с отмеченным флажком.
2. Отменённый, неуспешный или откатившийся импорт **ничего не сохраняет**.
3. Ошибка сохранения **не** откатывает уже созданный заказ.
4. Результат по каждому ключу:

| Результат | Условие |
|---|---|
| `SAVED` | Записи для ключа нет; обе стороны активны |
| `NOT_SAVED_MAPPING_EXISTS` | Запись для ключа уже существует (активная или отключённая, с любой парой) — **никогда не перезаписывается**; в т.ч. при одновременном создании другим пользователем (нарушение UNIQUE) |
| `NOT_SAVED_CONFLICT_IN_IMPORT` | В кандидатах один ключ с разными парами |
| `NOT_SAVED_COLOR_INACTIVE` | Одна из сторон к моменту сохранения архивирована |
| `NOT_SAVED_INVALID_SOURCE` | Исходный текст пуст или длиннее 64 |

5. Бизнес-отказы по отдельным ключам не прерывают сохранение остальных. Техническая ошибка откатывает всю транзакцию сохранения (не сохраняется ничего), заказ остаётся ACTIVE.
6. После сохранения пользователь видит итог: «Заказ импортирован. Сопоставлений сохранено: N.» и список несохранённых ключей с причинами; при технической ошибке — «Заказ импортирован, но сопоставления цветов не сохранены: <понятная причина>. Их можно добавить в Справочники → Цвета.»
7. Право: `reference.color-mapping.edit` проверяется на сервере; без него вызов отклоняется.

# 12. Order Management

- `SpecificationLine.color` — nullable immutable строка ≤ 64; тип, хранение (`order_management.item_specification_lines.color`, `order_item_revision_payload_line.color` `VARCHAR(64)`), payload и Public Query **не изменяются**.
- Строка спецификации хранит итоговый цвет: код (одинаковые стороны), `ВНУТРИ/СНАРУЖИ` (разные стороны), исходный текст или свой цвет.
- Ссылки на каталог в заказе не хранятся; исходный текст СО7 / `CLRNO` не копируется.

- Единственное изменение Order Management — аддитивный read-only контракт ограничений цвета (§10) и его регистрация как публичного сервиса; без новых зависимостей, без изменения парсера, валидатора импорта и транзакции.
- Детали — Order Management Specification §27.6, §28.5.

# 13. Warehouse, Production, Cutting

Подтверждено COL-000 (§4–§5.C): цвет — часть материальной идентичности по точной строке.

- **Warehouse:** приёмка создаёт / находит `MaterialReference` по `(article, color, size, unit_of_measure)` с `trim`; потребности пере-резолвятся точным сравнением. Любой корректно сохранённый цвет, включая разовый, проходит штатно. Каталог цветов Warehouse не читает.
- **Production:** агрегирует по `(materialCode, trim(color), unit)`; итоговый цвет используется без дополнительного шага.
- **Cutting:** модуль отсутствует (Stage 8 NOT STARTED); при появлении получает тот же зафиксированный цвет.
- `RAL7016` и `RAL7016|30`, а также `RAL7016` и `ral7016` — разные материальные исполнения.
- Точное сравнение цвета в Warehouse / Production не меняется; production-код Warehouse и Production не меняется (регрессия — тестами COL-050A/B).
- Архивирование цвета или отключение соответствия не меняет документы и не блокирует исторические материалы.

# 15. Security

## 15.1 Права

| PermissionId | Назначение |
|---|---|
| `reference.color.view` | Просмотр каталога цветов TMP, соответствий СО7 и состояния переключателя; доступ к пункту «Справочники» |
| `reference.color.edit` | Создание, архивирование и восстановление цветов TMP |
| `reference.color-mapping.edit` | Управление глобальными соответствиями СО7, включая сохранение из окна импорта |
| `reference.color-setting.edit` | Изменение общесистемного переключателя автоматического сопоставления |

- Формат соответствует `PermissionId` (три сегмента, дефис допустим).
- Объявляются в `CapabilityDescriptor` Capability `reference`; синхронизируются существующим механизмом Security.
- Все четыре права выдаются системной роли **Security Administrator** существующим bootstrap-механизмом (по образцу `WarehouseAdminNavigationAccessEnsure` / `DefaultSystemRolePermissionEnsureService`). Новые предопределённые бизнес-роли не создаются.
- На экране ролей область `reference` отображается как «Справочники» (`PermissionNamespaceGroup`).
- Проверка — на сервере в application-сервисах Reference Data; UI дополнительно скрывает / блокирует действия.

## 15.2 Разрешение цветов при импорте

- Пользователь с **полным** существующим набором прав импорта Order Management — `order.order.create`, `order.item.create`, `order.revision.edit`, `order.item.approve`, `order.order.approve` — может читать переключатель, активные цвета и результат сопоставления (`ColorImportResolutionApi`) и разрешать цвета текущего импорта **без** каких-либо прав `reference.*`.
- Альтернативно доступ к этим операциям чтения даёт `reference.color.view`.
- Только `order.order.create` (или любой неполный поднабор) **не** даёт доступа к операциям импорта.
- Reference Data проверяет набор прав импорта по строковым `PermissionId` без Maven-зависимости от Order Management; тест композиции в `tmp-bootstrap-app` подтверждает, что набор совпадает с правами, требуемыми `DefaultOrderImportService`.
- Без `reference.color-mapping.edit` пользователь не может сохранять или изменять глобальные соответствия; флажок сохранения недоступен.

# 18. Инварианты

1. Один одиночный цвет TMP = один уникальный (регистронезависимо) код = один UUID.
2. Сохранённый код неизменяем; сохранённые цвета физически не удаляются.
3. `|30`, `|МУАР`, `|МАСС`, `|ПРИТВОР` — отдельные цвета; `|` не означает двухсторонность.
4. `/` между двумя кодами итогового цвета — порядок внутри/снаружи; одинаковые стороны дают один код.
5. `/` в исходном тексте СО7 не означает две стороны и не разбирается.
6. Один ключ СО7 — не более одной записи соответствия.
7. Одна пара TMP может быть целью любого числа ключей СО7.
8. Нет каталога комбинаций.
9. Нет отдельной логики для «обобщённых» обозначений (`Цвет`, `Без цвета`).
10. `Без цвета` не равен `00` без явного выбора пользователя.
11. Одинаковые обозначения СО7 в одном импорте могут получить разные разовые цвета.
12. Разовое переопределение не изменяет глобальное соответствие; существующее соответствие не перезаписывается из импорта.
13. Глобальные соответствия из импорта сохраняются только после успешного confirm и не влияют на судьбу заказа.
14. Отсутствие прав `reference.*` не лишает пользователя с полным набором прав импорта возможности разрешить цвета своего заказа.
15. Разовый цвет не требует добавления в каталог и не блокирует downstream.
16. Переключатель `OFF` — импорт не меняет поведения.
17. Изменения каталога и соответствий не меняют immutable спецификации, документы, остатки и производственные данные.
18. Архивирование цвета атомарно отключает связанные активные соответствия после подтверждения; восстановление их не включает.
19. Начальное заполнение воспроизводимо, без дублей и без перезаписи пользовательских изменений.
20. Сопоставление использует текст поля `color` `.stxt`, а не `CLRNO`.
21. OM, Warehouse, Production не зависят от Reference Data.

# 19. Тестовые данные и переход (Q-01)

- Существующие пилотные заказы и складские остатки — **тестовые данные**. Автоматическая конвертация исторических строк цвета, слои совместимости для старых тестовых материальных идентичностей и изменение правил сопоставления материалов Warehouse **не** реализуются.
- Операции каталога цветов не изменяют существующие документы.
- До финальной приёмки (COL-060B) выполняется одно из (COL-060A):
  1. контролируемый сброс тестовых заказов, складских остатков и зависимых тестовых операций в `tmp_pilot` с сохранением пользователей, ролей, справочных данных (включая структуру складов и `reference.*`) и обязательной системной конфигурации; **или**
  2. подготовка чистой изолированной БД со всеми миграциями.
- Любая destructive-операция с БД требует: резервной копии (`scripts/pilot/backup-tmp-pilot.ps1`), проверки восстановления (`scripts/pilot/verify-tmp-pilot-backup.ps1`), предварительно показанного пользователю перечня затрагиваемых таблиц / SQL и **отдельного явного разрешения** пользователя.
- В рамках COL-005 и всех задач до COL-060A данные не удаляются и не изменяются.
- Реализация остаётся безопасной для будущих непробных данных: никакой код не изменяет существующие `color` и складские идентичности. Для будущих производственных данных включение переключателя на рабочей БД — отдельное решение о порядке перехода (без ретроспективных изменений).

# 21. Нефункциональные требования

- Единый стиль TMP UI Standard.
- Никаких скрытых автоматических изменений цветов существующих заказов.
- Серверная проверка прав и ограничений целостности независимо от UI.
- Технические поля аудита (`created_by/updated_by`, `created_at/updated_at`) на всех таблицах Reference Data (Constitution п.12).
- Импорт с полностью известными цветами не требует интерактивных действий.
- Нет подключения к Firebird, сетевых запросов к СО7 и фоновых заданий.
- 860 / 245 — начальные данные, а не лимиты; списки поддерживают поиск и фильтры.

# 22. Forbidden scope

- Карточки цветов, наименования, иерархия семейств.
- Изменение кода сохранённого цвета; физическое удаление сохранённых цветов.
- Генерация всех пар внутри/снаружи.
- Material Master / перепроектирование материалов; изменение точного сравнения цвета в Warehouse / Production.
- Разные окна / алгоритмы для `Цвет`, `Без цвета`, обычных и «формальных» обозначений; соответствие `Без цвета → 00` по умолчанию.
- Firebird / `CLRNO` в импорте `.stxt`.
- Загрузка 393 аналитических двухсторонних и 725 неподтверждённых обозначений.
- Обязательное внесение в каталог разовых цветов; дополнительные складские / производственные workflow из-за цвета.
- Ретроспективное изменение спецификаций, документов, остатков; конвертация исторических цветов; слои совместимости.
- Зависимость Order Management (Warehouse, Production) от Reference Data; изменение `OrderImportValidator`, парсера STXT, транзакции confirm.
- Общий платформенный Settings framework; универсальный framework справочников.
- Новые типы бизнес-документов и Domain Events для справочника.
- Межмодульные проверки «используется ли цвет».
- Перезапись существующего соответствия из окна импорта; сохранение соответствий до confirm.
- Новые предопределённые бизнес-роли.
- Обход Document Engine / Security / audit правил TMP для данных других Capability.
